# 站内消息与点赞

## 用户操作

- 登录后，页面顶部显示“消息中心”和未读数量；“我的”也有入口。
- 消息按新到旧排列，支持全部/未读、分页、手动刷新、单条已读和全部已读。
- 点击消息详情先标为已读，再进入商品、帖子或对应交易（交易卡片有提示和高亮）。内容被删除时，消息保留但不再提供跳转。
- 商品和帖子详情页分别提供点赞按钮及总数。登录后可点赞和取消；游客可看总数，点击会转到登录。点赞与商品收藏独立。

## 提醒范围

| 操作 | 收件人 |
| --- | --- |
| 买家申请预订（含订单留言） | 商品卖家 |
| 卖家接受、拒绝或确认交易完成 | 买家 |
| 买卖任一方取消交易 | 交易另一方 |
| 新评论 | 帖子作者 |
| 商品/帖子被点赞 | 商品卖家/帖子作者 |

自己操作自己的内容不产生提醒。取消点赞不删除历史消息，同一用户对同一内容反复取消、重新点赞仅首次提醒，避免刷屏。修改、删除评论不重发提醒。此轮没有新增商品评论或私聊入口；订单留言仍在交易详情中查看。

消息是网站内部的持久记录。登录且网页可见时，每 30 秒检查未读数量；回到窗口时立即检查。网页关闭或退到后台时不轮询，不具备浏览器系统推送、短信或邮件提醒。新消息不会自动标为已读；“全部已读”只处理本次已经加载过的最新消息之前的记录，后来到达的消息保持未读。

## 升级与数据

- 新增 `notifications`、`product_likes`、`post_likes` 三张表，不修改既有表字段，不重建数据库，不重置账号和内容。
- 当前 Render 启动项在 `CAMPUSLINK_INITIALIZE_SCHEMA=true` 时，于数据库事务和部署锁内新增缺失表；保留已有全部环境变量，无需更换密钥。
- 本地旧 PostgreSQL 环境先运行 `npm run upgrade:postgres`，它先备份再新增表；源码更新后应重新构建网页。
- 提醒只从新版本上线后的新操作开始生成，不批量补发旧交易和评论通知；旧商品、帖子仍可被点赞。
- 通知不存储订单留言、评论正文、邮箱或联系方式。访问及已读操作均按登录收件人鉴权；客户端不能指定收件人或创建消息。
- 点赞使用数据库唯一约束和原子冲突处理。业务变更与通知在同一事务中提交，业务失败时通知也回滚。
- 当前数据库备份工具按模型注册表处理新增表，云数据库与远程图片仍需要分别备份，未新增云端自动备份。

## 验收步骤

1. 两个不同浏览器会话登录 A、B；A 发布商品和帖子。
2. B 点赞商品/帖子、评论帖子、申请预订；A 检查未读消息与跳转。
3. A 接受预订；B 查看通知和交易。取消、拒绝和完成使用不同交易分支分别测试。
4. B 取消再点赞、刷新页面，数量正确；A 不收到重复点赞通知。
5. A 标记单条/全部已读、切换未读筛选、刷新，确认状态保留。
6. 检查 375/390/440px 宽度、网络失败重试、未登录拒绝及跨账号读消息被拒绝。

专业原型工具项目继续延期，不由消息中心或代码页面替代。
