- 部署仓库：https://github.com/Mikorchara/campuslink-deploy ，分支 main；已上线功能提交 `2c9d754`。
- 原前后端继续独立维护。内层源码 ZIP 配套提供 `src/` 与 `backend/`，打包提交和资源校验见 `.releases/<版本>/manifest.json`。
- Render 运行前端页面与 FastAPI；Supabase 保存 PostgreSQL 数据和上传图片。网站不依赖本机持续开机，但免费服务可能休眠或暂停，演示前应人工打开确认。

## 已完成的功能

1. 平台独立账号注册、登录、会话恢复、资料及联系方式。
2. 商品图片上传、发布、草稿、搜索分类、详情、本人编辑删除与状态管理。
3. 商品收藏、查看卖家联系方式、申请预订、接受/拒绝/取消和确认面交完成，并发接受保护。
4. 帖子发布、可选封面、分类搜索、分页、本人编辑删除；评论发布与本人管理。
5. 商品和帖子详情页点赞、取消、真实计数，独立于收藏。
6. 站内消息中心：预订、交易状态、帖子评论、收到的赞；未读数量、筛选、已读及详情跳转。

通知在网页可见期间约每 30 秒检查，回到窗口时立即检查；关闭网页后没有系统推送、邮件或短信。自己操作不通知自己，同一用户对同一内容反复点赞不重复通知。旧事件不补发。详细规则见 `MESSAGES_AND_LIKES.md`。

## 新机器本地启动

已验证 Windows 64 位、Node.js 24、Python 3.12。解压内层源码包后，在项目根目录执行：

```powershell
npm ci
npm run setup:backend
npm run setup:postgres
npm run start:release
```

首次安装需要联网，Node.js/Python 需预先安装。包内含编译网页；打开 http://127.0.0.1:8080/ 。后续可双击 `run-production.bat`。不要使用历史的免安装静态页面来验证真实业务。

更新已有本地 PostgreSQL 项目时，先停止网页服务，再执行 `npm run upgrade:postgres`、`npm run build:release`、`npm run start:release`。升级先备份再新增缺失表，不清空已有数据；备份失败则停止升级。不要覆盖旧目录中的 `.local/`、数据库或上传文件。恢复应使用独立新数据库，不能覆盖正在使用的库。

## 公网更新

按 `deploy/README.md` 构建配套部署源码，推送部署仓库 main，Render 自动部署。保留原环境变量和固定地址；`CAMPUSLINK_INITIALIZE_SCHEMA=true` 会在启动时新增缺失表。本轮只新增消息与点赞三张表，不改旧字段。将来的字段修改必须另做迁移方案。

云端密钥由负责人在 Render 管理，不写进源码、报告或 GitHub。Supabase 的数据库密码和 Storage Secret key 不是网页用户的登录密码。云端数据库与图片必须分别备份，当前没有云端自动备份承诺。本地备份工具会拒绝对远程图片存储生成不完整备份。

## 数据和演示账号

交接包不含真实数据库、用户上传文件、`.env`、`.local/`、测试账号凭据、依赖目录、缓存、Git 历史或私密备份。本地与公网数据库独立，本机账号不会自动出现在公网。

组员使用独立演示账号自行注册，不共享实际成员账号。建议准备 A（发布者）与 B（体验者）两套新账号，用不同浏览器或独立会话登录。演示内容模板见 `DEMO_DATA.json`；该文件只是输入参考，不会自动导入或改写网站数据。自动验收账号不作为课程演示账号对外提供。
