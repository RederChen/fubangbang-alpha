## 三 本轮消息与点赞

登录后，页面顶部显示消息入口和未读数量，“我的”也可进入。消息按时间倒序分页，支持全部或未读筛选、单条或全部已读。点击详情会先标记已读，再进入商品、帖子或高亮的对应交易。相关内容已删除时，保留记录并停止提供详情链接。

| 事件 | 接收提醒的人 |
| --- | --- |
| 申请预订及订单留言 | 商品卖家 |
| 卖家接受 拒绝 确认完成 | 买家 |
| 一方取消交易 | 交易另一方 |
| 帖子新增评论 | 帖子作者 |
| 商品或帖子收到点赞 | 商品卖家或帖子作者 |

### 提醒的使用边界

消息是站内持久记录，登录且网页可见时约每 30 秒检查一次，窗口恢复焦点会立即检查。网页关闭或退到后台时不轮询；当前没有手机系统推送、短信或邮件提醒。仅打开列表不会自动全部已读，旧事件不补发。

自己操作自己的内容不产生提醒。同一用户反复取消并重新点赞，仅首次产生提醒。修改或删除评论不重发提醒。此轮没有新增商品评论或私聊功能；交易留言仍在订单中查看。

### 点赞与数据一致性

商品和帖子详情分别提供点赞、取消及真实总数。点赞与商品收藏独立，游客可以看总数，登录后才能操作。数据库唯一约束与原子冲突处理防止重复计数；业务变更与通知在同一事务提交，失败的交易不会留下错误通知。

本轮只新增 notifications、product_likes、post_likes 三张表，不修改原有字段、不重置账号和内容。通知只向收件人开放，不保存订单留言、评论正文、邮箱或联系方式。

### 三个平台的分工

GitHub 保存配套部署源码；Render 使用 Docker 构建 Vue 页面并运行 FastAPI，浏览器同源访问 /api；Supabase 提供 PostgreSQL 与私有图片存储。图片经验证和 WebP 编码后保存，浏览器通过后端读取，不接收管理密钥。

Render 的免费实例可能休眠，Supabase 免费项目也有额度与不活跃暂停限制。固定链接不代表全天候服务，演示前需人工唤醒并检查。当前没有建立云数据库和远程图片的自动备份，二者应分别维护。

### 新机器启动

已验证 Windows 64 位、Node.js 24 和 Python 3.12。预装 Node.js/Python，解压内层包，在项目根目录依次执行以下命令；首次安装与下载项目内 PostgreSQL 需要联网。

```powershell
npm ci
npm run setup:backend
npm run setup:postgres
npm run start:release
```

浏览器打开 http://127.0.0.1:8080/ 。包内已包含编译网页，后续可双击 run-production.bat。不要用早期静态免安装预览验收真实业务。

### 已有环境升级

本地先停止网页，再运行 npm run upgrade:postgres，成功后重新构建和启动。升级先备份，只新增缺失表；备份失败则停止。不得用新包覆盖旧环境的 .local、数据库或上传文件。

公网在原部署仓库 main 更新，保留已有环境变量和网址。当前初始化设置会新增缺失表；将来的字段修改需要单独迁移。源码包不含 Git 历史，继续协作应取得各自仓库；再次打包需准备两个独立 Git 仓库。

包内不含真实 .env、密钥、用户数据库、用户上传文件、私密备份、node_modules 或虚拟环境。原电脑、公网和新机器之间不会自动迁移账号；新环境需自行注册，数据迁移必须单独安排。
