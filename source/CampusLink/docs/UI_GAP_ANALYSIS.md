## 一、一句话结论

**UI 原型完成度约 75%，但「成熟软件」所必需的 UI 完成度约 40%。**

差距不在视觉——视觉层面（色彩、卡片、排版、移动端适配）已经是可展示水准；差距在**闭环、状态、系统性与工程地基**三件事：

1. **闭环断了**：8 个规格页面只做了 6 个，缺的恰好是流程首尾两端——**登录/注册**（人怎么进来）和**发布商品**（内容怎么产生）。这两页不补，「注册→登录→…→发布商品→联系卖家」这条验收主链路走不通。
2. **没有状态**：全工程 0 个 loading、0 个骨架屏、0 个错误态、0 个 try/catch。接口一慢或一挂，页面就是白屏。
3. **没有系统**：Toast 提示在 6 个页面里各复制一份；186 处硬编码色值绕过设计 Token；接口层写好了却没人调用。

## 五、缺失的「状态 UI」——最容易被忽略的一类

一个成熟页面至少有 **5 种状态**，当前项目只实现了「有数据」这一种：

| 状态 | 定义 | 当前实现 | 典型场景 |
| :--- | :--- | :--- | :--- |
| **加载中** | 请求发出、未返回 | ❌ 完全没有 | 进闲置页、翻页、发布提交 |
| **空结果** | 请求成功但无数据 | 🟡 仅 `IdleMarket.vue:58` 一处 | 搜索无结果、分类下无商品、我还没发布过 |
| **错误** | 请求失败 / 网络断开 | ❌ 完全没有 | 后端没启动、弱网、500 |
| **部分失败** | 列表成功但图片挂了 | ❌ 无图片占位兜底 | 图片 CDN 抖动 |
| **成功反馈** | 操作已完成 | 🟡 仅 Toast 文案 | 发布成功、收藏成功、状态变更 |

> 现在工程里的 Toast 文案写的是「💡 发布闲置原型：Phase 1 规范中支持对接 POST /api/products 接口」——这是给**开发者**看的话，不是给**用户**看的。成熟软件面向用户时应为：「已发布，等待同学咨询」。

## 六、缺失的设计规范章节（设计系统完整性）

`variables.css` 已定义 80+ Token，但规范**只有色彩、圆角、间距、阴影、字号**五类，以下章节完全空白：

| 规范章节 | 现状 | 缺什么 |
| :--- | :--- | :--- |
| 色彩 | 🟢 有 Token | ⚠️ 但 186 处硬编码绕过（见下） |
| 字体分级 | 🟡 有 `--font-size-*` | 无行高、字重、字间距规范 |
| 间距 | 🟢 有 `--space-*` | ⚠️ 使用率低，大量裸 px |
| 圆角 / 阴影 | 🟢 有 | ✅ 相对完整 |
| **加载态规范** | ❌ | 骨架屏结构、spinner 尺寸、最小展示时长 |
| **空状态规范** | ❌ | 插画、主文案、行动按钮的统一格式 |
| **错误态规范** | ❌ | 错误分型（网络/业务/权限）、文案模板、重试按钮 |
| **表单校验规范** | ❌ | 触发时机（失焦/提交）、错误色、行内 vs Toast |
| **弹窗规范** | ❌ | 遮罩透明度、动效、按钮顺序、危险操作二次确认 |

| **图标规范** | 🟡 | 内联 SVG 散落各组件，无统一图标库与尺寸档位 |
| **暗色模式** | ❌ | 无 |
| **动效规范** | ❌ | 180ms / 250ms 散落硬编码，无缓动曲线变量 |
